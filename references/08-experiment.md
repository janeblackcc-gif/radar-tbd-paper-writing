# 08 · 实验设计与统计口径

> 适用语言：通用

## 一、探索性实验先写四段

跑之前写成：

```
假设         H：⋯
可观察预期   若 H 成立，应观察到⋯
验证方式     用什么数据、什么统计量判定
更新规则     若结果为 X 则⋯；若为 Y 则⋯
```

**更新规则要预先规定失败该怎么解释**，防止事后把失败重述成别的东西。

本项目的两条实际更新规则：

> 「全失效是合法科学结果，进入结论边界；**不得为获得好看曲线修改场景或 seed**。」
>
> 「若生成或契约失败，判定为调用/契约缺陷，先修复，**不把失败解释为算法性能**。」
>
> 「conditional RMSE 必须与成功率和分母共同解释。」

## 二、预承诺收窄规则

对每一条待验证的性能归因，**预先写好收窄规则**。

模板：

> 若 `full − variantA` / `full − variantB` 的效应量 95% CI 覆盖 0，按预承诺规则把主张降级为「整体机制（bundled module）」，**不事后寻找有利场景、不改门限**。

规则触发后的定稿写法（保留设计价值，只不确认独立性能增益）：

> 「两个 95% 置信区间均包含零，差异在统计上不可分辨。」
> 「消融结果尚不能区分⋯各自的独立贡献，本文因此将性能归因于⋯的整体作用。」

后处理检查也要写进正文：

> 「门限取值在查看结果之前确定，主文不从敏感性结果中改选更有利的门限。」

措辞按 [03-diction.md](03-diction.md) 第二节的正名表处理——正文写「在查看结果之前确定」，不写「预注册」「冻结」这类流程治理词。

## 三、样本量按区间精度设计

**不照抄范文。**

推导链：

1. 主结论需要区分的效应量是多少
2. 该效应量下需要多窄的置信区间
3. 反推每条件样本量

本项目：30 次时 95% Wilson 半宽约 0.17 → 不够 → 核心条件取 **每条件 100 次**（范文是 500 次，不跟）。

次要敏感性轴可用 30–50 次，但**必须在文中说明样本量依据**。

## 四、指标矩阵

只报告自定义的总体成功率会被判不合格。按「**自变量 × 领域惯用指标**」矩阵补齐。

本项目的六行矩阵：

| 自变量 | 输出指标 |
|---|---|
| SNR | 成功率、GOSPA、OSPA、检测跟踪率、连续性 |
| 杂波率 / 量测点数 | 成功率 |
| 检测概率 P_D | 成功率 |
| 一级幅度门限 / P_FA | 成功率、门限敏感性 |
| 二级确认门限 | 成功率 |
| 编队规模与拓扑 | 成功率、几何失配退化 |

**自定义指标可以保留，但不能是唯一主证据。**

传统 TBD 领域必须给的：检测率、RMSE、GOSPA/OSPA、cardinality RMSE、门限敏感性。

## 五、次要轴的方法集要显式列出

次要实验轴如果跑的方法集比主实验少，**必须在文中显式列出每条轴各含哪些方法**。

否则读者拿后面的图去对主图会发现曲线数对不上而无从解释。

本项目的实际披露：

> 描述性轴运行了缩减的方法集：Top-1 与 GM-PHD 从未在杂波、门限和检测概率轴上执行；杂波轴还去掉了 position-only；几何轴只运行 Full 与 Top-1。

## 六、分析地位标注

每项分析标注三种地位之一：

| 地位 | 含义 |
|---|---|
| **confirmatory** | 预注册、见结果前冻结、可作主证据 |
| **descriptive** | 描述性，不作因果主张 |
| **post-hoc validation** | 事后补算，明确标注 |

放在补充材料的 analysis-status 表里。

### 面对「主指标有漏洞」的质疑

**先查已有产出里是否已经存了能反驳它的补充指标**，离线聚合成描述性证据并明确标注 descriptive-only。

**不要重跑已揭盲的实验来制造支持性结果。**

本项目实例：评审指主成功指标不惩罚多余轨迹 → 从已密封的逐 trial 诊断离线聚合出 GOSPA 121.0（可部署方法中最低）、cardinality RMSE 0.00、输出 10.00 条/帧对 10 个真值，反过来支撑结论。

同样的手法可以把「注册但未执行」的补充分析离线补算出来，并加硬自检确保与官方列一致（本项目：1080/1080 一致）。

### 机械决定的指标值必须自己说明

若某个补充指标的数值由**接口或输出结构机械决定**而非来自方法能力，必须自己在原文写明，否则会被当作夸大。见 [07-code-consistency.md](07-code-consistency.md) 第十节。

## 七、seed 管理

| 池 | 用途 | 纪律 |
|---|---|---|
| development | 调参、调试 | 不进论文 |
| holdout（旧） | 已揭盲的确认性实验 | 地位不变，作一致性佐证；**不得复用于任何新干预实验** |
| 新 confirmatory 池 | 新一版主证据 | 预注册 manifest，与前两池均不重叠 |

**正式 seed 数值不得出现在任何进入论文的产物**——包括图注、表注、脚注和补充材料。

展示用实例的选取按机械规则，规则写进正文（见 [02-narrative.md](02-narrative.md)）。

## 八、统计措辞

### pointwise ≠ family-wise

从一组逐条件置信区间**推不出**「处处成立 / 一致优于 / uniformly」。

只能写：

> 「所有预设逐点区间的下界为正」

并在方法或协议节明确一句：

> 「所报告区间为逐点区间，不主张族系覆盖。」

### 统计结论要给三个槽位

**是什么量、和什么比较、得出什么结论**——缺一即视为未完成。

```
✗ 「区间覆盖零」
✓ 「两个 95% 置信区间均包含零，差异在统计上不可分辨」
```

### 效应量与区间

配对效应量 + bootstrap 95% CI（本项目：10,000 次 seed-cluster bootstrap）。

报告差值时给绝对单位（percentage points），不要只给相对百分比。

## 九、消融的归因粒度

**一次消融改变了几个部件，结论就只能覆盖这几个部件的整体。**

写归因句之前必须**回读该消融分支的实现**，把它实际改动的变量全部列出来再决定主语粒度。

不能拆分时，在**摘要**主动补一句不可辨识声明。详见 [04-hedging.md](04-hedging.md) 第十节。

正交子消融（只去 A / 只去 B / 双去）应纳入核心消融组，而不是留作补充。

## 十、基线的公平性

必须在正文交代：

1. **基线调参的出处与锁定时点**（在见本方法结果之前锁定）
2. 至少一个 **sanity benchmark**——在该基线原文的适用场景上跑一遍，证明实现无误（本项目：GM-PHD 跑标准可分场景、GT-ML-PDA 跑类范文的单群场景）
3. 基线的输入与本方法**是否同源**（同一 case、同一量测）

缺 sanity benchmark 时，「基线表现差」会被读成实现问题而非方法差异。

## 十一、失效结果照实报告

全条件失效是**合法科学结果**，写进结论边界。

不要：

- 为获得好看曲线修改场景或 seed
- 把契约/调用缺陷解释成算法性能
- 只报告成功区间而不给失效边界

conditional RMSE 这类条件指标必须**与成功率和分母共同解释**——单看条件 RMSE 会把「只在容易的样本上成功」读成「精度高」。
