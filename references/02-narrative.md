# 02 · 结构层：逐章写法

> 适用语言：通用

## 摘要

两段。

**段 1**：问题 → 机制 → 输出。
**段 2**：设置 → 成绩 → 边界（边界只作结尾一句）。

### 硬规则

1. **报告结果的部分，第一条实质结论必须是正面结果。**
2. **做了基线比较，比较结论必须进摘要。**
3. 适用范围限定只放在结尾分句。
4. 禁止用「消融不能区分⋯」「证据不足以说明⋯」或最弱的那条结论开头。

以下两条按**结构性缺陷**而非措辞问题处理，发现即整段重写：

- 摘要首句是局限或失败
- 摘要通篇没有一句说明本方法相对已有方法的位置

本项目的真实事故（上一代摘要，受"不要过度声称"单向规则支配）：

```
this pre-GO draft intentionally reports no performance claim
until all registered cells and scientific contribution gates pass.
```

修复后：

```
FCM-ML-PDA 的成功率在 4 dB 以上超过八成，8 dB 及以上进入稳定区间；
在全部九个 SNR 条件下均高于 GT-ML-PDA、CFAR+GNN、GM-PHD 与 GM-CPHD，
差距在 4--8 dB 区间最大。
```

定稿自查一句：**只读摘要的人能否知道这篇论文做成了什么、比谁好。**

### 数字粒度

给聚合量级（区间、量级、相对关系），不搬运逐条件原始计数。

「在全部九个条件下均优于四类基线，差距在中段最大」 ✓
「4 dB 仅 8/100」 ✗（细粒度留正文）

粒度惯例对照目标期刊近期 2–3 篇同类论文校准，不套用单一规则。

### 摘要的自含性优先于额度规则

防御句额度（见 [04-hedging.md](04-hedging.md)）**不适用于摘要**。主结果必须连同它的适用边界在摘要里完整陈述，成绩句与边界句可以同段并存——删掉边界反而构成夸大。额度规则管的只是正文里的重复。

## 引言

**单线递进，不分小节，每段只做一件事。**

```
应用场景与研究对象（定义 + 2–3 个实例）
  ↓
为什么难
  ↓
当前主流做法为何在此问题上失效
  ↓
逐个点名该路线现有扩展各自的具体缺陷
  ↓
一句缺口句 ← 全文靶心
  ↓
两句话概括本文方法    ← 方法名在这里才第一次出现
  ↓
贡献列表
  ↓
全文组织
```

### 第一句：先立对象，不立技术设定

**检查判据**：如果读者必须先接受本文的问题设定才读得懂第一句，就往上退到领域对象本身。

| 反例（旧英文稿） | 正例（定稿） |
|---|---|
| "A lower radar reporting threshold preserves evidence from weak targets but also admits more false plots." | 「群目标是指由多个紧密间隔、运动特征相似的目标构成的集合，如编队飞行器、导弹群和集群飞行器等。」 |

反例的问题：首句直接陈述技术困难，而这个困难的主语（群目标）此时还没有定义。

同时禁止的开场：「近年来⋯受到广泛关注」「本文方法具有优越性」。

定义只占一句，不要展开成术语综述。

### 缺口的三步写法

缺一步就会被读成贬低前人：

1. 先用**前人自己的口径**承认最接近工作的实际贡献
2. 把缺口陈述为「**某项信息或结构尚未被用于某个环节**」，不是「前人方法做不到、效果差」
3. 用一句「换言之，X 尚未被用于 Y」封口，指名具体是哪项信息、用在哪个环节

全程不比较优劣，不写「未能」「失败」「不足」。

批评现有方法时必须**逐个点名并给出失效机理**：

> 「某方法在阶段 A 有效抑制了 X；然而当条件 C 成立时，其阶段 B 仅利用 Y，未将 Z 用于约束 W」

禁止「现有方法存在局限」式概括。对最接近的同类方法尤其要**先肯定其有效的那一步，再指出其未做的那一步**。

### 缺口句与贡献第一条一一对应

缺口句全篇只出现这一次。它必须与贡献列表第一条严格对应：**缺口说缺什么，贡献一就补什么**。对不上说明缺口找错了或贡献排序错了。

### 从引言删除的三类段落

- 验证方式 / 交付物清单段
- 次要数学性质段（移入方法章一句）
- 结果边界预告段（留给结果章）

### 贡献列表

只写**正面能力陈述**：「提出 X，其通过 Y 实现/改善 Z」。

不进引言的内容：实验统计量、置信区间、消融限定语、样本量设计——全部搬到结果章。

不写关于写作规则本身的元叙事（「实验结论不预先写入贡献列表」「本文不否定这些方法的适用范围」）——这类句子是把工作流程约束误写进了正文。

允许在**摘要末尾**用一句话声明适用条件（「本文结论在 ⟨条件⟩ 下建立」）。这是范围声明，与在引言里预先交代方法在哪些条件下会失效是两回事，后者不写。引言本身的限定句额度是 **0 句**（见 [04-hedging.md](04-hedging.md) 第二节的位置白名单）。

贡献条数按实际给。条目是否带量化结果因刊物而异，红线是不写自辩、不写元叙事，不是一律禁数字。

## 相关工作

**按方法族组织，不逐篇罗列。**

每族的固定写法：

1. 按对方论文**准确复述其机制三到四句**
2. 沿**单一可比维度**（关键信息从哪里进入推断）做差异化
3. 给**适用性判据**收尾：「其适用性取决于观测模型与计算预算」

章末划定本文不覆盖的范围。

### 禁止的写法

| 禁止 | 原因 |
|---|---|
| 「有结构 / 无结构」「考虑了 / 没考虑」二分 | 直接判稻草人 |
| 「不能处理」「未闭合」「不适用」 | 按**引用准确性缺陷**对待，不是语气问题——没有原文或实验支撑就一律不写 |
| 「现有方法仍存在不足」 | 泛化，替代了真正的差异说明 |

差异化改用正向表述：点名最接近的一两项工作，沿几条具体技术轴（输入信息、建模假设、中间表示、输出对象）逐项对照，再说明在本文设定下它未使用哪条信息而本文用了。

**审稿人要的是可核对的差异，不是对前人的评价。**

### 论断—引用绑定

叙事重写时最易漂移的就是这个：从范文搬来的论断会挂到本文书目里不完全对应的文献上。

修法是**放宽论断措辞去适配手上的引用**，而不是硬挂或换引用：

| 改前 | 改后 |
|---|---|
| 「顺序多目标 ML-PDA（MT-ML-PDA）⋯\cite{Bu_2021}」 | 「顺序 ML-PDA 方法⋯\cite{Bu_2021}」（删掉张冠李戴的缩写） |
| 「基于等效量测或随机有限集的方法能够有效跟踪群中心 \cite{A,B,C}」 | 「另一类方法利用群的整体运动或结构先验进行跟踪 \cite{A,B,C}」（放宽论断使三个引用都站得住） |

> 导师和同门对本方向文献烂熟，缩写归属错一个一眼就会被抓。

压缩相关工作时执行**删句不删引用**：被删句子的引用键全部并入保留句，改前改后的 `\cite` 集合必须一致并附 grep 对账结果。

## 方法章

每个小节固定节拍：

```
动机句 → 对策 → 公式 →（必要时）算法框或图
```

### 动机句

形式：「**由于 X 无法直接获得 / 无法直接使用，需要⋯**」

要指出这一小节面对的**具体缺口**：该量无法直接获得、精确解不可计算、复杂度随规模爆炸、只能在更粗粒度上观测。按各小节的真实缺口变换句式，不要把同一个模板句在全章重复。

**定稿检查**：逐个小节只看首句，凡首句直接给符号定义、直接进公式、或直接罗列步骤的，一律补动机句。

### 实现细节移出正文，但数值参数留下

分界线不在「参数 vs 机制」，而在这两类之间：

| 类别 | 处置 |
|---|---|
| 排序键、去重键、内部配置键名、内部路线名 | **移出**，正文只写机制（「候选按确定性几何分数排序、去重并有界截断」，不给键的细节） |
| 容差、上限、步长、资源上限、门限工作点 | **留在正文并就地给出数值**（见 [06-evidence.md](06-evidence.md) 第一节） |

**从代码写方法章最典型的失败就是把排序键、去重键这类实现细节当成方法。** 但反过来把容差和上限也一并移走，会留下一堆「按预设容差」的空壳限定语——那是 [03-diction.md](03-diction.md) 第十五节判定必须返工的缺陷。

本项目定稿的实际落点：`04_method.tex` 内联了容差 `max(75 m, 15%)`、上限 20 与 12、资源上限 `2^20`、容差 `1e-4`、步长 `{50,20} m`、粒子比例 `0.7`；补充材料里一个都没有。而排序键、去重键确实只写了机制。

### 压缩方法章的不可删区域

章节压缩是数学错误的高发场景。动手前先划定：

- 推导主线的**中间步**
- 每个符号的**首次定义**
- 随机量的**分布声明**

三类高发硬伤：

1. 只留结果式加一句「可证 / 严格抵消」——关键抵消必须让读者**在式子里看见它发生**，不能只被告知
2. 符号未定义就登场
3. 为对齐范文而新写本方法**并不具备**的性质断言（「且可并行」「存在闭式解」）——仿写行文可以，把范文方法的性质安到自己方法上是技术错误

可以砍的只有重复警句、实现参数和冗余铺垫。压缩后逐符号复查首次出现处是否已定义，并回读被压缩推导是否仍闭合。

汇报压缩结果前跑 diff 逐条对照，**不得在实际删掉了推导步或定义行的情况下声称「零删减」**。

## 结果章

### 顺序

```
5.1 实验设置（含主文场景参数表）
5.2 典型仿真过程展示 ← 同种子证据链
5.3 主结果（SNR 曲线）
5.4 消融
5.5 敏感性（杂波 / 门限 / P_D / 几何失配）
5.6 计算代价
```

### 同种子证据链

**汇总统计之前，先用同一个实例把证据链走完一遍。**

仿真类论文的典型形态：

```
场景参数表 → 真值 → 含噪观测 → 代表帧原始量测（目标/漏检/杂波分类）
→ 中间检测或关联结果 → 最终输出（各方法叠加）→ 失败案例 → 统计曲线
```

整条链共用**同一实例和同一坐标范围**。坐标范围取一次算好：取所有被展示的真值、量测、中间结果和最终估计点的并集，扩展为等边正方形并加 5% padding——保证局部结构不被单图缩放人为放大。

**正文必须写明该实例是按什么机械规则选出来的**，以排除择优展示：

> 「展示用仿真实例的选取方式为：以本方法为参考，选取在 16 dB 成功跟踪且在 0 dB 未通过成功判据的同一随机种子，成功与失败实例共用该种子；代表帧取观测窗中间帧。」

选择规则先写死再执行，且规则本身要进正文。

> 只给汇总曲线会被直接质疑实验是否真跑过。本项目导师的原话是「没有看到最基本的编队仿真图，让人高度怀疑 AI」。

### 段首

一律以**结论式陈述**开头：先说观察到了什么，再引表、图与统计量。

两种开头都算违规：

| 违规形式 | 例子 |
|---|---|
| 问句式 | 「性能随 SNR 如何变化？」 |
| 空转指路式（更常见） | 「图 3 给出了⋯的结果」——形式上是陈述句却没有传递任何结论 |

定稿后用全文问号计数和段首 grep 复核。

> 注意目标期刊口味：禁用问句适用于 IET/TAES 类传统工程期刊。ML 会议把 "Does X help?" 当标准段首，照搬反而削弱行文。

### 每图 2–3 句解读

写成「**图 X 显示【现象】，这是因为【机制】**」。现象一句、机制一句起步；主结果图可以更长，但任何一段都不允许只念坐标轴上的数。

**机制必须紧跟现象**，不要攒到后面统一处理——读者读到图时拿不到解释，读到解释时已经忘了图。

没有证据支持机制时**只写现象**，不要为了凑句式编一个原因。

解读句必须逐张**对照渲染出来的图面**核对，见 [06-evidence.md](06-evidence.md)。

### 图注

写图面上**有什么**，不写图**不是**什么。

删掉这类自辩型图注：「它只展示⋯不含⋯」「仅用于说明」「总体性能仍以完整实验为准」「该图不代表⋯」。它们是在替审稿人预设质疑，反而提示图有问题。这类限定属于评价口径段，不属于图注。

图表标题里的定性描述必须逐条对着数据核：把「多数 / 不下降 / 显著」换成具体计数，并让标题主动说出该图里的负面结果。

### 讨论是否独立成章

按目标期刊体例定。默认建议：**若不强制独立 Discussion，直接把讨论内容就近并入对应结果小节**。

若体例强制保留，讨论章只写结果章承载不了的内容（跨结果的综合、与外部工作的对比、边界与未来工作），**不得复述已报告过的现象**。

本项目实测：讨论章整章并入结果章后，同一条限定语被重复三遍的主要来源随之消失。

## 结论

两段，按此顺序：

1. **成果段**——方法一句话定位 + 有效工作区间 + 呼应主结论。数字与摘要一致，不引入正文未出现的新数字。
2. **边界段**——适用条件，以未来方向收尾。

禁止三件事：

- 自贬式收尾（「在这些扩展完成前，本方法应被视为⋯的工程方法」）
- 首次出现的防御论述
- 正文没铺垫过的新结论

段数与篇幅按范文的结论节校准，不要硬套固定页数或条目数。

## 定稿前的两项段落审计

1. **跨章去重**——同一句告诫 / 限定语 / 说明在两个章节各出现一次时删掉其一，保留**论断发生处**的那一次。
2. **拆装夹告诫**——一段里同时装了两组结果和一条方法学告诫时拆成独立段，并把告诫排到两组结果之后，不要让它夹在中间打断因果链。

## 承重内容不得用指针替代

必须在正文自足、不能用「详见补充材料 / 见附录」代替的：

- 定义
- 成立条件
- 算法输入边界
- 支撑正文主张所必需的结论

只有可选的扩展证据才放补充材料。既写不进正文又非承重的，**整句删掉而不是留一个指针**。

指针本身不是缺陷（版面受限的会议依赖它），**用指针替代承重内容**才是。

「详见补充材料」类指针按密度控制：每页都出现会被读成偷工减料。通读时统计一次并压到个位数。本项目期刊定稿的实际交付是**正文 0 处指针**。

### 正文与补充材料互相独立

若期刊单独托管补充材料，把两者做成**互相独立的两份文档**：

- 正文不引用补充材料的编号
- 补充材料也不引用正文的章节 / 公式 / 图表编号
- 两者只共享数值宏与图件

交付前双向 grep 各查一次。
