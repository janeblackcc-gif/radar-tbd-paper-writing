# 09 · 改稿流程与交付验收

> 适用语言：通用

## 一、逐章硬停点

**禁止一次性交付全文。**

流程：

```
写完一章 → 编译出该章样张（新文件名）→ 交付样张 + 本章改动说明
→ 停止 → 等明确回复 → 才动下一章
```

### 第一章是定调之作

**第一章的修改意见就是后续所有章的风格基准。第一章未过审不得预写后续章节。**

本项目实测：执行窗口累计跳过三次逐章门禁后，规则升级为「**跳过 = 整章返工**」。改为逐章后，六章六轮硬停点全部走完，问题在当章闭环，累计 15 处必改全部在交付当轮修掉。

对比：一次性交全稿两次，两次都被判「读不下去」整轮返工。

### 也可按工作包停

后期改稿轮可改为按工作包设停点：

```
WP1 词汇 → WP2 结构 → WP3 图表 → WP4 参考文献
```

同样禁止合并交付。

## 二、只批注了第一章不等于后面合格

**必须把首章批注归纳成「错误模式清单」，先交确认这份规则，再用它重写全部章节。**

批注按形态分流：

| 批注形态 | 处理规则 |
|---|---|
| 高亮 | 用词可疑 → 查证后改，或说明保留理由 |
| 删除线 | 直接删 |
| 下划线 + 备注 | 评估价值与成本后给建议，交裁决 |

查证后保留的，要在交付说明中记录结论和依据——**保留可以，静默保留不行**。

产物：一份 grep 清零证明文件（本项目：`m4_zh_jargon_grep_proof.txt`，44 个模式，源码与渲染文本双范围零命中）。

## 三、三层验收

**写作质量是与科学正确性正交的独立验收维度。**

本项目的两次盲区：

| 轮次 | 已通过的检查 | 仍被判 |
|---|---|---|
| r5 | 宏对账、claim 边界、术语一致性、统计口径 **全过** | 「臃肿、跳跃、不知所云、没有形成连贯的论文叙事」 |
| r6 | 结构重构完成、六章逐章过审 | 「major revisions，连我这关都过不了」+ 70 条批注 |

因此每轮验收必须三层分做，各有独立的机械化手段：

| 层 | 手段 | 交付物 |
|---|---|---|
| **claim 纪律** | 关键句 grep + 主张—证据闭环表逐条销账 | 销账表 |
| **叙事连贯** | 逐章复述因果链 + 按范文量表自比 | 自比量表 |
| **词汇** | 禁用词双范围 grep 清零 | 扫描表达式 + 退出码 |
| **排版** | PDF 页级渲染目检 | 目检记录 |
| **改动可信度** | 逐页字符数 delta 归因 | 残差 = 0 |

## 四、三列对照单

每轮改动产出一份逐条对照单，格式固定：

```
清单号 → 文件:行（改后行号）→ 原文 → 新文 → 依据
```

**「数据核对后无需改动」的项也照样登记**，并给出核对结果。本项目 r11 轮 13 条里有 3 条是这种（如 #6：「新 CI：+0.33 pp [−0.22, +0.89]⋯原句与新数据方向一致」）。

## 五、PLAN_DISCREPANCY：范围外问题登记不动手

发现但超出本轮授权范围的问题：**只登记，不顺手改。**

```markdown
## PLAN_DISCREPANCY
#5  正文 :133 优势区间表述过窄，不在本轮清单 → 建议下轮处理
```

下一轮开头附一张「**上轮 PLAN_DISCREPANCY 归宿总表**」，逐条标注：已修 / 已归档 / 备案保留 / 用户确认。

本项目 r11 轮登记 9 条，下一轮全部闭环。

### 例外：已知错误必须改

如果范围外的句子被新数据**推翻**（即留着就是错的），照改，但同时登记为范围偏离项、写明**可单独回退**，交终审裁决。

不要为了守住 diff 范围而留一句已知错误。

### 推论

发现清单外的不一致（如同一句限定语在两处措辞略有差异）时，**默认登记上报而不擅自统一**——把「要不要统一」交回给授权方。

任何超出清单的改动都要单独列出并标注性质：**是语义修改还是纯读感修改**，不得混进语义改动里静默吸收。否则对方无法从 diff 判断哪些改动动了内容，整份修改的可信度会一起塌掉。

## 六、逐页字符数 delta 归因

每轮文字改动后做一次，**残差必须为 0**：

```
whole-document delta : +163
  abstract delta     : +40
  section 5.3 delta  : +123
  residual           : +0
```

残差非零说明有未登记的改动。

配套脚本：`scripts/page_delta.py`。

## 七、删减去向清单

**砍内容可以，砍了不报不行。**

每章汇报随附一份去向清单，每条含：

```
原文位置 | 内容摘要 | 建议去向（已被 X 覆盖 / 移入补充材料 / 建议删除）
```

分类：

- 已被别处覆盖 → 直接删并留指针
- 未覆盖且有价值 → 记入清单随章交裁决

本项目事故：某章汇报「六步公式主线零删减」，实际删了推导中间抵消式与排序认证段。记过一次，此后交付必须主动分列「合并操作如实汇报」与「压缩操作如实汇报」两张表。

判词：**「零修改零删减」的自我声明与事实不符，比删减本身更严重。**

## 八、写作与科学内容分离

纯行文修订轮的授权边界必须书面锁定：

### 锁定项（无权改）

```
章节骨架 · 数值宏 · claim 范围 · 统计表述 · 术语决策
图表集合 · 结论式开头规则 · 渲染输出路径
```

### 自由度（可自由重构）

```
句序 · 段落切分 · 节内段落顺序 · 措辞
```

### 四步工作法

1. 先列出本小节的核心论断及其证据来源
2. 指出待改句与理由
3. 只重写已确认范围
4. 交付「已改内容 / 刻意保留内容 / 待确认项」三分类清单

**不得新增事实、结果、比较、原因、缩写或引用。** 材料不支持处标注待确认而不自行补全。可能改变技术含义的语言修改一律保留原文并说明原因。

反向同理：数据轮不改行文。

## 九、批注原件保护

用户或导师批注过的文件是**原件**：

- 只读
- 留 SHA-256 备份
- **重渲染一律换新文件名，绝不覆盖**

本项目为此专门加过一条红线：某个已交付的渲染 PDF 被批注后，它连同备份一起进入禁止覆盖、禁止删除清单。

## 十、PDF 页级渲染目检

**图必须在页面渲染级别逐页目检，不能只看生成脚本跑通。**

只在页级可见、且能连续躲过多轮文字审阅的缺陷：

| 缺陷 | 说明 |
|---|---|
| 轴标题被裁 | 标签旋转后长于图高，`bbox_inches="tight"` 救不回来。PDF 文本流以 "dian computation time" 开头，"Me" 掉在图外 |
| 图例列出该面板不存在的曲线 | 三面板共享图例，但某面板没跑那条方法 |
| 图内标签截断 | 长中文标签溢出 |

本项目这两个缺陷「**只在页级可见，且已躲过三轮模拟审稿**」。

### 数据驱动的图元参数换工作点后要专项复查

图元的位置、范围、分箱数如果由数据算出，换工作点后可能失效——这类问题脚本不报错。

## 十一、排版问题的处理顺序

优先靠**内容自然延长 + 字号档位**解决，不要用强制分页 / 浮动屏障。

本项目实测：

| 尝试 | 结果 |
|---|---|
| 在结论前插入 `\FloatBarrier` | **更差**：总页数 20 → 21，新增第 14 页仅 329 字，版面明显断裂。已回退 |
| 正文自然延长 + 算法块 `\small` → `\footnotesize` | 空白页消失且页数不变 ✓ |

**强制手段常常把一个空白页变成两个。**

### LaTeX 换行陷阱

源码里的一个换行会被渲染成一个空格。因此任何「渲染后不允许有空格」的相邻构件——`a/b` 形式的分数或计数、数值区间、宏与紧跟其后的符号——必须写在同一源码行，或在行尾加 `%` 吃掉换行。

否则会渲染出 `0/ 500` 这类断裂。**这类错误在源码里完全看不出来，只能在渲染后的 PDF 上逐处目检。**

## 十二、面对外部严格评审

1. **先核实评审证据本身**——重点确认它依据的是当前版本而不是过期产物

   本项目实例：一组被标为 Major 的 findings 经查基于三天前的过期 PDF 文本提取，照做会把已删除的旧措辞加回去。

2. 确认成立的条目**分批执行**，每批跑完：值校验 + 重编译 + PDF 页级目检
3. 禁用表述用文本抽取计数为 0 收口
4. **抽取工具会因换行切断短语造成假阴性**——命中 0 时先换更短的片段复查

## 十三、风格争议以更高权威为准并留档

同行评审可以「无硬性规定」为由驳回的风格项，一旦上级明确要求就必须执行，**不要拿旧裁决当挡箭牌**。

本项目实例：交叉审稿 07-26 裁决「结果小节疑问句开头 → 驳回该 Minor，无期刊禁令证据」；三天后导师明确「不要使用问句」→ 最终稿全文问号计数为 0。

## 十四、阶段依赖顺序不可交换

写成硬门，不是建议：

```
阶段 0 中文母稿骨架
  → 阶段 A 锁定模型
  → 阶段 B 重建实验
  → 阶段 C 重构结构与图表
  → 阶段 D 翻译
```

**母稿逻辑和实验未过审之前不得进入翻译或排版阶段。**

本项目的门禁写法：

> 「当前门禁 M4：中文母稿全稿交导师确认；未确认不进入阶段 D。」

改动前的做法是直接在英文稿上逐句润色，导师反馈「英文不地道，逻辑不大通顺」——因为问题在中文逻辑层，润色英文治不了。

## 十五、交接文件写成小节级映射蓝图

零上下文的新窗口应当**不需要追问就能动笔**。

交接文件必备：

```
1. 任务一句话
2. 授权方判决原文（引用，不转述）
3. 必读输入顺序
4. 叙事规则 N 条
5. 逐节映射蓝图：现稿 → 新稿去向、保留项、删除项、目标篇幅
6. 删减去向纪律
7. 硬停点
8. 红线清单
9. Exact First Action
10. Bootstrap Prompt（可直接粘贴的启动提示词）
```

判词：

> 「我在新的执行窗口做的时候像个无头苍蝇一样什么信息都没有，主控窗口应该提供完整的信息，让执行窗口可以直接就上手做，也能减少歧义和错误的概率。」

## 十六、并行窗口按目录切分

写作与实验并行时**禁止交叉写入**：

| 线 | 只改 | 交付 |
|---|---|---|
| 实验线 | 数据、图、宏、生成器 | 一份 digest：计数表 + 宏名对照 + 按证据强度排序的可写解读 + **claim 措辞上限与禁区** |
| 写作线 | 正文 | 只经宏引用数字 |

产物用平行文件名隔离，合并入库由把关线统一授权。

写作线以 digest 为唯一事实来源，数字一律引用宏，禁手抄。

## 十七、呈现口径由作者裁决

不要在正文和图里加过程注解：

```
✗ 「σ=0 取自核心网格（7745HX）；σ>0 于开发机执行」
✗ 「40-seed 分母」（当口径已统一时）
✓ 「σ_g=0 与各非零水平合并计算，分母均为 \FCMBFiveGeoSeedDenominator{}」
```

「这批数据在哪台机器上跑的」对读者无信息量，只暴露工程过程。来源说明留在项目内部决策记录里。

## 十八、方法论沉淀放在会被读到的地方

本项目上一代的沉淀（938 行「零上下文接手指南」）失效，三个原因都要避免：

| 失效原因 | 修法 |
|---|---|
| 只写了「能不能这么说」（claim 层），没写「读起来怎么样」（语言层）——938 行里「中文/措辞/句式/段落/翻译腔/行文」六词合计只出现 1 次 | 内容治理与语言治理都要写 |
| 「不要过度声称」写成单向硬规则、无平衡条款 → 直接催生「本稿有意不报告任何性能主张」的摘要 | 成对规则 |
| 钉死绝对工作根（`Set-Location` 到已废弃的目录），必读清单里的绝对路径条目已失效 | 放进 skill；一律用仓库相对路径；不钉死实验结果目录名 |
