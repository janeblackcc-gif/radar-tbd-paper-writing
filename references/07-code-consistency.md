# 07 · 论文与代码一致性

> 适用语言：通用

从代码仓库起草论文时，最容易出的不是文笔问题，是**论文描述与实现不符**——而这类缺陷被评审抓到一律是 Major。

## 一、追调用链，不用 grep 首个命中

**写方法或评价指标的实现细节前，必须从生产入口逐跳追调用链到真正被执行的那个函数。**

仓库里常并存多个功能近似的实现，写错的那一个会成为论文与代码不符的 Major。

本项目实例（唯一被判 Major 的论文—代码不符）：

| 论文写的 | 实际生产调用链 |
|---|---|
| 「基于逐帧代价的全窗动态规划」 | target sets → CV arc 匈牙利链接 → 删除短于 4 帧的 arc → 100 m 截断代价的全局 truth-to-arc 匈牙利分配 |

自记根因：**写补充材料时用了 grep 找到的 DP mapper，而没有追生产调用链**。修复需读 4 个锚点文件逐行核对。

### 动作

1. 从**生产入口脚本**开始（不是从函数名开始）
2. 逐跳记录：`入口 → 调度 → 执行 → 指标计算`
3. 遇到同名 / 近似命名的多个实现时，确认哪个在生产路径上
4. 写作时引用**实际路径上那个文件的行号**

## 二、伪代码逐行对着实现校验

**按实现的真实执行顺序写，不能按叙述方便重排。**

### 四处最容易写反

| # | 项 | 本项目实际错误 |
|---|---|---|
| 1 | **循环起点** | 写 `for k = 2..N`，实现是 `k = 1..N` |
| 2 | **两步操作的先后** | 写"先归属分配再传播"，实现是先传播再求归属 |
| 3 | **批处理在循环内还是循环后** | 平滑写在循环内输出，实现是循环结束后一次批处理 |
| 4 | **初始化的位置** | 混在循环里，实现是独立的循环前区块 |

修复后的写法：

```
初始化（独立的循环前区块）
for k = 1 .. N
    if k > 1: propagate
    form point state from particle weighted mean
    one-to-one MAP ownership assignment
end
run the fixed-lag smoother as one batch pass over the complete
    particle, weight, and ancestor history
```

### 逐行标注代码依据

对照单里每行伪代码挂一个 `文件:行号`：

```
| 伪代码行 | 代码依据 |
|---|---|
| 帧循环 k = 1..N | fcm_run_scene_follower_tracker.m:69 |
| 传播先于归属 | fcm_run_scene_follower_tracker.m:70--89 |
| NCV 传播与槽位吸引合并为一次调用 | fcm_transition_follower_particles.m:6--14 |
```

**顺序错位在评审里等同于方法描述错误**，不是排版问题。

### 顺序修正常带出正文的连锁修改

| 改前（04_method.tex） | 改后 |
|---|---|
| 「后续每帧更新前，各 follower 以粒子加权均值形成点状态⋯」（暗示第 1 帧不走该路径） | 「**帧循环自第 1 帧起**，每帧更新前各 follower 以粒子加权均值形成点状态⋯」+ 新增一句「因此第 1 帧共有两次一对一 MAP 分配：初始化的一次以槽位预测形成的点状态为输入，帧循环内的一次以初始化后的粒子加权均值为输入。」 |

## 三、多路分派要按真实层数写

描述降级 / 级联策略时，按实现里**真实的层数和顺序**写。

| 改前（写成两层） | 改后（实现是三层级联） |
|---|---|
| 「对更大分量，算法采用带上界剪枝的分支定界搜索⋯资源上限与容差数值详见补充材料。」 | 「对超出该上限的分量，算法**先尝试第二条精确路线**：按规范顺序逐个处理量测，状态只记录当前仍有边相连的槽位的占用情况，当同时保留的槽位数不超过预设上限（12）时⋯结果仍为精确值。**两条精确路线都不适用时**，才转入带上界剪枝的分支定界搜索⋯」 |

依据：`fcm_association_dispatch_plan.m:22-39`。

**补写中间层时用机制描述它**（做什么、状态是什么），不要临时引入全文别处没有的专业名词。

## 四、方法环节映射表

方法章末尾附一张表，使每一段方法描述都能反查到实现：

| 方法环节 | 主要实现来源文件 | 本章对应位置 | 核验状态 |
|---|---|---|---|
| 候选生成 | `fcm_stage1_*.m` | §4.2 | 已核验 |
| 关联求解 | `fcm_association_dispatch_plan.m` | §4.4 + 算法 1 | 已核验；置换回归通过 |
| 跟随目标跟踪 | `fcm_run_scene_follower_tracker.m` | §4.6 + 算法 2 | 正式数值以冻结策略为准 |

这张表有两个作用：读者可反查；**写作时不敢凭印象描述算法**。

本项目实测 11 行。

## 五、实现细节移出正文，但数值参数留下

**移出**：排序键、去重键、内部配置键名、内部路线名——正文只留机制。从代码写方法章最典型的失败就是把这类实现细节当成方法。

**留下并就地给出数值**：容差、上限、步长、资源上限、门限工作点。这几类是方法的一部分，读者需要就地看到（见 [06-evidence.md](06-evidence.md) 第一节、[02-narrative.md](02-narrative.md) 方法章一节）。

留在正文的限定语不能只给名义不给数值——见 [03-diction.md](03-diction.md) 第十五节。本项目一轮就展开了 6 处「预设 X」：

```
pair-distance tolerance      max(75 m, 15% of slot spacing)
width cap                    12
node expansion budget        2^20
convergence tolerance        1e-4
grid step                    {50, 20} m 与 {10, 5} m/s
measurement-particle ratio   0.7
component size cap           20
```

每一个都逐条回到冻结配置核对，并在提交信息里写明依据文件。

## 六、不得把范文方法的性质安到自己方法上

仿写复杂度段或性质段时，逐句自问：**这条性质我的实现真的具备吗？**

| 事故 | 问题 |
|---|---|
| 「⋯且组间可并行，总代价与组数线性增长」 | 「组间可并行」与本文 §4.5 的多组机制直接矛盾（本文多组是顺序处理）。这句是仿写时新写的 |

高发项：「可并行」「存在闭式解」「可增量更新」「无需调参」「复杂度与 N 无关」。

## 七、技术形容词降级为可核查事实

描述实验环境、执行方式和资源占用时，**逐词自问「这个形容词能被哪一条配置项或日志字段逐字证明」**。

证明不了的一律降级：

| 推断性描述 | 可核查事实 |
|---|---|
| single-threaded | single process / serial execution / no parallel workers |
| 高效实现 | （删除，或给出实测 runtime） |
| 实时可行 | （删除，除非有实时性测试） |

再补硬件、系统和软件版本这些确实可查的信息。

> 这条属于 claim 强度，不属于措辞。

## 八、复杂度段的写法

1. 给出与实现一致的数量级（本项目：`O(T·M·2^M)` / `O(2^M)`）
2. 给实测 runtime 区间作为对照
3. 明确写出该复杂度对应的是**哪一条求解路线**（若有多层级联）
4. 不写实现不具备的性质

## 九、把「过程管理」改写成「实验做了什么」

审计、冻结、封存、清单、commit hash、执行窗口、××单元 —— 这些描述的是**你的工作方式**，读者只需要科学动作和科学量。

**自查法**：把句中的治理词替换成它对应的科学事实：

| 治理表述 | 科学事实 |
|---|---|
| 「执行 N 次」 | 「进行 N 次 Monte Carlo 仿真」 |
| 「主成功判据保持不变」 | 「跟踪成功的判定标准为⋯」 |
| 「留出种子 / 证据状态 / 清单哈希」 | 「每种条件 N 次独立 Monte Carlo 实现，无已完成运行被剔除」 |

**替换不出科学事实的句子通常整句可删。**

完整词表见 [03-diction.md](03-diction.md)。

## 十、评价器行为的披露

评价指标里由**接口或输出结构机械决定**的部分必须自己在原文写明，否则会被当作夸大。

本项目实例：

> cardinality RMSE = 0 是固定输出合同的机械结果，不能当成基数估计能力优于基线的证据。

补写：

> "zero cardinality RMSE reflects the declared fixed-cardinality output contract and is not a cardinality-estimation claim."

同类：评价器不惩罚 unmatched arcs、成功判据在歧义时保守判失败 —— 这些都要在方法或评价小节披露一次。
