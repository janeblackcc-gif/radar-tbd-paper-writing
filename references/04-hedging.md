# 04 · 防御性表述治理

> 适用语言：通用

这是本项目**耗时最长、反复最多**的一层。根因是「不要过度声称」被写成单向硬规则、没有配平衡条款，于是被单向执行到自我否定——上一代摘要末句是「本稿在所有注册单元和科学贡献门通过前，有意不报告任何性能主张」。

## 一、成对规则

**每一条禁止夸大的规则，旁边必须配一条禁止自我削弱的规则。**

| 禁止夸大 | 配对的禁止削弱 |
|---|---|
| 不写未经实验支持的性能归因 | 做到的必须写进摘要；最强结果不得只活在图里 |
| 消融改了几个部件，结论只能覆盖几个部件 | 不因归因受限就用失败开头，正面结论仍排在最前 |
| 不外推到未验证的维度与规模 | 适用范围写一次即可，不反复致歉 |
| 不写「首次/据我们所知第一个」 | 也不因此放弃陈述贡献，改用具体未解决问题 |
| 确定性步骤不加「近似/可能次优」 | 真实近似照实写，不美化 |
| 不把范文结论当自己方法的证明 | 参数锚定引第三方已发表取值范围，不放弃锚定 |
| 防御句总量设上限（第二节） | **真实且唯一的边界不因额度被删**，超额只删稻草人与重复陈述 |

## 二、定量预算

把「别过度设防」变成可计数、可验收的硬指标。

### 全稿上限

用范文标定：数一篇目标期刊同类论文里的限定句数量，以它为全稿上限。

**经验值：20 页正文内不超过 10 句。**

本项目改稿轨迹：40+ 句 → 全文 5 处。

### 同一条边界最多 2 次

主张处 1 次 + 结论呼应 1 次。两处说同一件事，**后一处不加码**。其余全删。

### 位置白名单（只有三处）

1. 实验设置 / 评价协议段——一次性交代成功判据与样本角色
2. 结果主张句**内**的限定词
3. 结论章的适用范围段

引言与相关工作写 **0 句**。

### 摘要不计入额度

摘要按**自含性优先**：主结果必须连同它的适用边界完整陈述，成绩句与边界句可以同段并存。删掉边界反而构成夸大。

额度规则管的只是正文里的重复。

摘要里保留哪类限定取决于性质：

| 类型 | 摘要 |
|---|---|
| 适用范围类（「结论在二维刚性几何条件下建立」） | 通常应留 |
| 归因不确定性类的长句 | 不必进（消融不可辨识声明另见第十节，那里给了两条并列解法） |

### 验收

定稿前用关键短语 grep 逐条数额度：

```
不能  不等同于  并不表示  不作为  尚不能  不得  无法被理解为  不应据此
```

实际出现次数**不得超过上限**；低于上限不需补足，只核对位置白名单内的必写项是否齐全。把计数结果写进交付检查单。

**超额时删哪几句由第三节的两问判定。** 两问都答「是」的真实唯一边界不因额度被删——此时只允许合并同一边界的重复陈述，并在交付检查单写明「实测 N 句，其中 M 句经两问判定必留」。

> **验证要在最终 PDF 抽取出的文本上做，不在 `.tex` 上做**——宏展开、条件编译和已移出编译的章节都会让源码计数失真。若几处措辞不完全一致，用它们共有的**最长特征子串**去数，否则整句精确匹配会漏计。

### 不计入额度的三类必写项

以下三类是防夸大的诚信底线，**删掉反而构成夸大**，不受额度约束：

1. 摘要（自含性优先，见本节末）
2. **评价器机械行为披露**——指标值由接口或输出合同机械决定时必须自己写明，见 [07-code-consistency.md](07-code-consistency.md) 第十节
3. **pointwise 非 family-wise 声明**——见 [08-experiment.md](08-experiment.md) 第八节

## 三、删一句防御性表述的判据：两问

1. **读者真的会做出这个错误推断吗？**
2. **被它反驳的那个说法，读者能否从本文已写出的内容里合理形成？**

两问只要有一个否，这句就是**稻草人**——直接删，而不是软化。

> **例外（一律判必留，不适用本节）**：若该说法来自**指标接口、输出合同或采样口径的机械结果**，读者必然会形成它。这类披露句是诚信底线，见本文第二节「不计入额度的三类必写项」。

默认行为通常是把 caveat 越改越长，所以「删而不是软化」这个动作要显式执行。

同源规则：不要反驳没人会提出的主张，也不要用一种实验设计去否认它本来就推不出的结论。

## 四、AI 腔的两个显著标志

### 1. 「本方法是 X，不等同于 Y」式自我澄清

删除。

**但不要连坐**：「把 A 归给 B 而非视为 C」这类用于**下定义或指定归属**的对照句是合法中文。

判别方法：看它是不是**带假想反驳语气**——

| 删 | 留 |
|---|---|
| 「不能被理解为⋯」 | 「温度桥承担 SMC 采样器中间分布的作用，与辅助粒子滤波不同之处在于不做前瞻重采样」 |
| 「不应据此认为⋯」 | 「该量归属于观测模型而非运动模型」 |

批量清洗「不是 X 而是 Y」会误伤合法句式——只删前一类。

### 2. 否定清单排比

```
✗ 「本方法不是 X、不是 Y，也不主张 Z」
```

改成**一次正向定位加一处具体对照**。

重复出现的约束清单和否定式排比是评审最容易识别的机器写作特征，与语言无关。

**验收**：对被拆开的每条限制取一个关键词全文计数，除第二节允许的主张处与结论呼应外不得再出现（即**不得重新聚成清单**）。

## 五、三段式重写模板

每一处需要交代局限的地方按此写：

```
正面结论（用数据陈述做到了什么、机制为何成立）
  ↓
边界条件（限定成立范围，作为界定句收尾）
  ↓
建构性后续路径（能消除该限制的具体后续设计）
```

**硬约束**：这是重排与改写，不是放宽结论——数值、统计口径和主张范围必须与改前逐字一致，**边界条件本身一句都不许删**。

### 禁止用否定句领起结果段落

```
✗ 「消融结果尚不能区分⋯」（作为段首）
✓ 「⋯在 4 dB 以上成功率超过八成；该消融不区分两个部件各自的独立贡献。」
```

### 局限段以「下一步怎么做」收尾

固定两句：一句陈述边界事实，一句给出可行的推进方向。

> 「在既定资源限制下未能评估 11 目标；更紧的分解、结构化界、并行实现与实时性评估因此是更大编队的优先方向。」

**归因必须诚实**：只有当边界确实来自实现或资源约束时才如此归因。属于方法固有的局限**不得包装成资源问题**——一旦被评审识破，代价远大于当初把话说软的收益。

## 六、删掉让步式与辩解式连接

```
仍然需要  不得不  尽管如此  虽然…但是
```

改成中性陈述加理由：

| 改前 | 改后 |
|---|---|
| "They are nevertheless required because…" | "They are retained because…" |

这是**改语气不是删内容**：真实局限照写，但只陈述事实、全文只说一次，不反复致歉，也不预先替审稿人反驳自己。

## 七、边界分发，不集中堆放

每条边界条件放在**它所限定的那个结果旁边**，不要集中堆到一个专门章节里。

一个除了局限性没有别的内容的「讨论」章应当拆散，把每句边界表述分发到对应的结果段和结论段——顺带消除同一条限定语被重复三遍的主要来源。

仅当目标期刊明确要求独立的 Discussion 或 Limitations 小节时才保留，且该节应**指回具体结果**而不是重述它们。

## 八、无证据的存在性断言

凡是暗示「效应真实存在只是没测出来」的词，都是无证据的存在性断言：

```
被掩盖   被淹没   已开始影响   实际上存在
```

只能写成**纯观测描述**。

配套自查：同一段里对**相同量级**的现象不得一处判「波动」一处判「机制」——这个双标审稿人会抓。

## 九、创新性声明与缺口句

### 先分清缺口的两种类型——处理方式相反

| 类型 | 缺口来自 | 正确写法 | 反例 |
|---|---|---|---|
| **文献空白型** | 「没人做过 X」 | 落成一个**具体未解决问题** | 覆盖性断言 |
| **设计逻辑必然型** | 从本文模型关系**推导**出来 | **否定式反而更安全**：「仅 A 不足以保证 B，因此还需 C」 | 改写成「X 尚未被用于 Y」 |

**第二类最容易被规则误伤。** 例：

> 「运动模型扩展不能只发生在单条参考轨迹上，而应贯穿候选生成、刚体传播和成员级关联评分。」

这句读起来是否定式，但它**不是文献主张**——它是从「转弯率同时决定参考传播与槽位旋转」这个已建立的模型关系推出的必然性，不需要任何文献支持，也没有哪篇论文能推翻它。

若机械改写成「共享转弯率尚未被用于槽位旋转」，反而**升级成了文献穷尽性主张**，风险更高——只要有一篇反例就崩。

**判据**：问一句「这句话要成立，需要我查遍文献吗？」

- 需要 → 文献空白型，按下面处理
- 不需要（从本文模型就能推出）→ 设计逻辑必然型，**保留否定式**，只做具体化

具体化的方向是把「不能只⋯」换成指名道姓的机制：

> 「仅在参考轨迹层面引入转弯模型，不足以保持编队几何与关联评分的一致性；转弯率还需进入候选生成、槽位传播和成员级评分。」

### 文献空白型：不要建立在这两类说法上

**只要有一篇反例就整段崩**：

```
✗ 「该方向研究很少」
✗ 「首次 / 据我们所知第一个」
```

**首选改写**：落成一个**具体未解决问题**：

> 「本设定下尚未解决的是：如何把已知槽位直接放进由过门限标记点构成的关联边缘中」

这比任何覆盖性声明都更难被推翻。

确需正面声明新颖性时用**组合式并附检索边界**：

> 「未见同时具备 A、B、C 的既有方法（截至 YYYY-MM-DD 检索未发现直接先例）」

但不要为凑新颖性堆砌连词项——限定条件过多本身会被读成心虚。检索只能支持「截至某日未发现直接先例」，不能证明绝对首次。

> 注意「X 尚未被用于 Y」**本身也是覆盖性断言**，只是比「首次」弱。用它之前确认该断言的范围窄到你能守住。

## 十、消融的归因粒度

**一次消融改变了几个部件，结论就只能覆盖这几个部件的整体。**

写归因句之前的强制动作：**回读该消融分支的实现，把它实际改动的变量全部列出来**，再决定主语粒度。

这一步是最常被跳过的。本项目连续三轮被判 Major，都是同一件事：把双部件消融的增益归因给其中一个部件。

若不能拆分，有**两条并列的合规解法**：

| 解法 | 做法 | 本项目采用处 |
|---|---|---|
| **A** | 摘要里的归因句**本身就用消融实际覆盖的粗粒度主语**（「支持编队联合处理机制整体的必要性」），显式的不可辨识声明放在结果章与结论章各一次 | 中文定稿 |
| **B** | 摘要在**成绩句之后**补一句不可辨识声明 | 英文投稿版 |

**选择规则**：摘要若已能用粗粒度主语把归因说准，用 A；若成绩句不得不点名单个部件，必须用 B。

两条解法的共同底线是**不能等评审来抓**，也**不能让不可辨识声明抢在成绩句之前**。

配套的前置机制：预承诺决策规则，见 [08-experiment.md](08-experiment.md)。

## 十一、结果段的位置审计

改稿时**只读每段首句**做一次审计。

首句若是失效条件、局限或「本文不能说明什么」，把它移到段尾，并补上被它挤掉的正面结论。

**唯一例外**：结论本身为阴性的段落（如未测出显著差异的消融）。此时首句仍应是该实验的**结论陈述**，而不是免责声明。

## 十二、不要给确定性步骤加不确定修饰

「近似」「可能次优」只写在真实存在近似的地方。给一个确定性求解步骤加上这类修饰，是另一种形式的不诚实。

同理，把方法固有的两阶段分解写成：

```
✗ 「不等同于完整联合估计」（防御姿态）
✓ 「该两阶段策略是对完整联合估计问题的一种近似分解」（自然陈述）
```

保留下来的那一处限定，优先改写成自然陈述而不是防御姿态。

## 十三、结论章的三条禁令

- 自贬式收尾（「在这些扩展完成前，本方法应被视为⋯的工程方法」）
- 首次出现的防御论述（结论不是引入新 caveat 的地方）
- 正文没铺垫过的新结论

## 十四、claim 强度改动必须同步全部镜像位置

任何 claim 强度的修改都要同步到：

```
摘要 · 引言 · 结果 · 结论 · 图表标题 · 图注
```

改完用该 claim 的关键词全文搜索确认无漏网。**只改一处，下一轮复审会把剩下几处逐个抓回来。**

典型场景：从一组逐条件置信区间**推不出**「处处成立 / 一致优于 / uniformly」——那是同时推断（family-wise）措辞。只能写「所有预设逐点区间的下界为正」，并在方法或协议节明确一句「所报告区间为逐点区间，不主张族系覆盖」。
